## 架构总览（一句话）

> **PS 跑 Linux，独占"蓝牙协议栈 + 键盘采集"；PL 保持现有游戏 RTL 与 HDMI 时序链路一行不改，只新增"键码注入通道"与"按键合并层"。**

```
蓝牙键盘 --BLE--> 板载 BT 模块 --HCI UART(仅 TX/RX)--> PS UART0(EMIO) --> Linux(BlueZ + HID Host)
   --> /dev/input/eventN --> 用户态守护进程 --> EMIO GPIO 写键码
   --> PL 按键合并层（与物理 K4~K7 做 OR） --> key_ctrl（不改） --> 菜单/贪吃蛇/俄罗斯方块（不改）
```

**不变量（重要）**：`video_timing.v` / `clk_hdmi.v` / `hdmi_tx.v` / `tmds_encoder.v` / `serializer_10to1.v` / 三个场景模块 / `key_ctrl.v` **全部不动**。
新工程走**新分支**，`p2d3` 冻结为比赛保底基线，**绝不原地改造**。

## 关键硬件事实（2026-10-16 手册核实）

| 信号 | 引脚 | 侧 | 说明 |
| --- | --- | --- | --- |
| `BT_FM_UART_TXD` | **D18** | PL Bank35（3.3V） | 蓝牙 UART 发送 |
| `BT_FM_UART_RXD` | **E19** | PL Bank35（3.3V） | 蓝牙 UART 接收 |
| `BT_nRESET` | **E18** | PL | 蓝牙复位（Linux `hci_bcm` 需要 `shutdown-gpios`） |
| `BT_HOST_WAKE` | **M17** | PL | 蓝牙→主站唤醒 |
| `BT_WAKE` | **M18** | PL | 主站→蓝牙唤醒 |
| PS 调试串口 | MIO48/49（Bank501，**1.8V**） | PS | **已被 USB-UART 占用** → 蓝牙必须用 **UART0 经 EMIO** |
| 按键 | K4~K7 | PL | 保留，作演示冗余与保底输入 |
| 扩展口 | JP1/JP2 = 72 GPIO | PL | 备用 |
| PS USB Host | 标准 A 型 **J3**（**需短接跳线 J5** 才有 5V） | PS | **备选键盘路线，Linux 下零 RTL** |

### ⚠️ 头号风险：蓝牙 UART 没有流控线

手册只引出 **TX/RX 两根线，没有 CTS/RTS**。后果：Linux `hci_bcm` 无法做硬件流控，
理论上存在主机发太快、模块来不及收而丢字节的风险。

**缓解**：HID 键盘流量极低（单次按键约 10 字节、按键率 < 20 Hz），115200 下几乎不可能溢出。
按 115200 起步；异常则降速 57600 / 9600（蓝牙控制器初始化时会协商波特率）。
**若蓝牙最终跑不通，退路是 USB 键盘插 J3 —— PetaLinux 下无需任何 RTL 改动、零风险。**

## Phase 1 · LUT 瘦身回退 —— ✅ 已完成（2026-10-16 实测）

| 指标 | 回退前（`p2d2`） | 回退后（`p2d3`） | 变化 |
| --- | --- | --- | --- |
| Slice LUT | 21974（41.30%） | **6071（11.41%）** | **−15903（−29.9 个百分点）** |
| Slice Register | 2169（2.04%） | 1305（1.23%） | −864 |
| WNS / WHS | +14.806 / +0.114 | **+17.663 / +0.117** | 时序更宽松 |

做法：删掉俄罗斯方块的"逐格保存方块颜色"（`brdcol`/`b2c`/`b3c`）与两处 `bg_at` 渐变场地，
保留倒角立体感、菜单渐变、跑马灯、呼吸、脉冲、闪白等全部动效。

**结论：现有 LUT 11.41%、BRAM 0/140 全空，资源极其宽裕，后续不必再为省 LUT 牺牲画面。**

### 资源红线（所有升级项的前提）

| --- | --- | --- |

## Phase 2 · 架构升级：PS+PL 协同 + 板载蓝牙键盘（**新主线**）

### 2.1 PL 侧改动清单（尽量小）

| # | 改动 | 内容 | LUT 增量 | 风险 |
| --- | --- | --- | --- | --- |
| P1 | **Zynq PS 顶层替换** | 新建 Block Design（ZYNQ7 Processing System），把现有全部游戏 RTL 作为 PL 自定义逻辑挂进去 | 0 | 中（工具流程） |
| P2 | **EMIO 引出** | PS **UART0** → EMIO（2 根）到 PL 引脚 D18/E19；PS **GPIO** → EMIO（3~4 根）到 E18/M17/M18（`BT_nRESET` / `BT_HOST_WAKE` / `BT_WAKE`） | 0 | 低 |
| P3 | **PS↔PL 键码通道** | **定案：改用 EMIO GPIO**——PS 以并行线直接写键码电平，PL 直接读。**零 AXI 互连、零额外时钟**（跨 PS/PL 时钟域只需 P5 的两级同步器），BD 极小；20 根 EMIO GPIO 绰绰有余（方向键动作 5 根 + 预留） | +100~200 | 低 |
| P4 | **按键合并层** | 物理 K4~K7 与"PS 注入键码"按 OR 合并后喂现有 `key_ctrl`——**`key_ctrl` 与游戏模块一行不改** | +50~100 | 低 |
| P5 | **上电复位/同步** | PS 侧信号跨到 PL 时钟域（25.2 MHz）需两级同步器 + 边沿检测（PS 写的是电平，需转成脉冲） | +50 | 低 |

> P4/P5 是**唯一真正新增的 RTL**，合计约 +200~350 LUT，可在纯 PL 工程里先把功能做出来验证，
> 之后搬进 Block Design 即可 —— 所以**这部分可以现在先做，不等 Linux**。

### 2.6 保底与预埋（重要策略）

1. **冻结 `top_game_console_p2d3.bit`**：它是"上板验证通过、纯 PL、零依赖"的比赛保底方案。
   PS+PL 版本在**新工程目录**推进，直到 M3 通过才考虑替换。
2. **先做 PL 侧 P4/P5（不依赖 PS）**：在现有纯 PL 工程里先加"按键合并层 + 合成键码源（先用 LFSR 伪造键码）"，
   综合对比 LUT/WNS 无回归后出新位流上板验证。这样 Linux 一旦通了，**即插即用**。
3. **物理 K4~K7 永远保留**：既有演示冗余，也是答辩时"纯 PL 亦可独立运行"的证明。

## 已确定的决策

1. **工程性质改为 PS+PL 协同**（不再维持纯 PL）。
2. **键盘外接 = 必须项**，通道选 **板载蓝牙 EMIO**；PS 侧跑 **PetaLinux / Linux**；构建主机 = **本机 WSL2**（**实际定为 Ubuntu 22.04.5 LTS**——PetaLinux 2026.1 宿主白名单不含 24.04.5；VirtualBox/VMware 不采用）。
3. **保底退路 = USB 键盘插板上 J3**（Linux 下零 RTL，需短接 J5）；再后才是 PS/2 键盘。
4. **`p2d3` 冻结为比赛保底基线**，PS+PL 版本走新工程分支。
5. **PL 侧游戏/HDMI RTL 保持不变**，只新增"键码注入 + 按键合并层"。
6. **K5 长按 = 加速软降**（保持现状），不改硬降。
7. **LUT 瘦身已完成**（41.30% → 11.41%），资源红线放宽。
8. **启动方式改为 BOOT.bin**（FSBL + 位流 + 内核 + 设备树），SD 卡迭代、QSPI 定稿。
9. **PS↔PL 键码注入通道 = EMIO GPIO**（不使用 AXI BRAM / UIO），零 AXI 互连、BD 极简。
10. **PS+PL 工程不原地改造**：新建 `D:\FPGAproject\MizarZ7_PLPS\`（Vivado）+ WSL2 `/home/plnx/mizar_z7`（PetaLinux）；PL 游戏 RTL 以 **module reference** 方式挂进 Block Design。
