# Mizar Z7 嵌入式游戏机 · 下载上板教程

**适用硬件**：微相科技 Mizar Z7（XC7Z020-2CLG400，`xc7z020clg400-2`）
**适用软件**：Vivado 2026.1（Vitis/PetaLinux 2026.1，仅重建时用到）
**目标**：把已经编译好的设计与镜像上板，看到游戏画面。

**好消息**：位流和系统镜像**都已经编译好了**，你**不需要重新编译任何东西**，照抄下面步骤即可。

## 第 1 步：认口（先对丝印）

板上接口的丝印名称和手册里的叫法不一样，先对照下表找准位置，**插错口是最常见的失败原因**：

| 接口 | 板上丝印 | 手册叫法 | 用途 |
| --- | --- | --- | --- |
| HDMI 输出 | **HDMI TX** | HDMI1 | 接显示器。**必须插这个口** |
| USB 下载 | **USB JTAG**（Micro-USB） | USB 下载接口 | 接电脑，下载位流 / 写 Flash |
| USB 串口 | **USB UART**（Micro-USB） | USB 串口（3.6.7 节 p29） | 看 Linux 启动日志（CP2102 芯片，**不是下载口**） |
| SD 卡槽 | **Micro SD / TF 卡槽** | SD Card（3.6.6 节 p28） | 插 SD 卡，启动 Linux |
| 电源输入 | **DC5V**（桶形座） | 电源输入 | 接 5V 适配器 |

**最容易认错的两个**：

- **HDMI RX**（手册叫 HDMI2）：另一路 HDMI **输入**，本工程没用它，插错会黑屏。
- **USB UART**：这是**串口**，不是下载口。要下载必须插 **USB JTAG**。

> 手册依据：3.3 节（p15）"板载了 USB JTAG Cable 的下载电路，用户只需要一根 Micro USB 线
> 就可以对 ZYNQ 进行下载程序"；3.6.6 节（p28）Micro SD 卡槽接 PS SDIO0、Bank501 MIO[40-45]；
> 3.6.7 节（p29）USB 串口用 CP2102，接 PS UART1、Bank501 MIO[48-49]；
> 3.7.1 节（p32）HDMI1 = HDMI TX，3.7.2 节（p34）HDMI2 = HDMI RX。

## 第 2 步：设置启动模式拨码 J1（很重要，30 秒）

板上有一个 **2 位拨码开关 J1**（手册 3.2 节，p14；丝印是 **J1 / SW4**，旁边印有 MODE 设置表）。

```
        ┌─────────────────────────┐
        │  MODE  │   1   │   2    │
        ├─────────────────────────┤
        │  JTAG  │  ON   │  ON    │  ← 方式 B（Vivado 下载位流）
        │  QSPI  │  OFF  │  ON    │  ← 方式 C（Flash 固化）
        │   SD   │  OFF  │  OFF   │  ← 方式 A（SD 卡启动）
        └─────────────────────────┘
```

**按你选的方式拨**：方式 A → 两位都 **OFF**；方式 B → 两位都 **ON**；方式 C → 1 是 OFF、2 是 ON。

> 手册 3.2 节（p14）："ZYNQ 的启动模式通过 MIZAR Z7 开发板上的拨码开关 J1 的 ON/OFF 状态去配置……
> 支持三种启动模式，分别为：SD 卡启动，QSPI 启动，JTAG 模式。"
>
> 原理（Figure 3-4，p15）：开关 1 ↔ MIO[5]，开关 2 ↔ MIO[4]，**ON = 逻辑 0**。
> SD 启动要求 MIO[5]=0 且 MIO[4]=0 → 两位都 OFF；JTAG 要求 MIO[5]=0、MIO[4]=0 → 两位都 ON
> （Zynq 上电时仍会按 JTAG 档位让 PS 停在可下载状态，PL 用 JTAG 配置）。

## 方式 A：SD 卡启动（推荐，完整 PS+PL 工程）

> 特点：**不需要电脑**，上电即出画面；PS 跑 Linux（后续蓝牙键盘方案的平台）。
> PL 位流由 FSBL 从 `BOOT.BIN` 里加载，**在 Linux 启动之前 PL 就配好了** —— 所以即使 Linux 有问题，
> HDMI 画面也应该先出来。这是很好用的故障切分点。

### A.1 格式化 SD 卡

把 SD 卡格成**一个 FAT32 分区**（分区表用 **MBR**，不要 GPT）。

> Windows 操作：插入读卡器 → 右键分区 → 「格式化」→ 文件系统选 **FAT32** → 开始。
> 容量大于 32 GB 时 Windows 不给 FAT32 选项，请改用 ≤32 GB 的卡。

### A.2 拷贝文件到 SD 卡根目录

把下面这些文件**直接拷到 SD 卡根目录**（不要在卡里再建子文件夹）：

```
BOOT.BIN      ← 必拷
image.ub      ← 必拷
boot.scr      ← 必拷（U-Boot 启动脚本）
system.dtb    ← 建议一并拷
```

> **为什么只要 FAT32、不需要 ext4 分区？**
> 本工程的根文件系统是 **initramfs**（设备树里 `bootargs` 写着 `root=/dev/ram0`），
> 它已经**打包进 `image.ub`** 里了。所以不需要第二个 ext4 分区，也不需要 `petalinux-package --wic`。
> `boot.scr` 在 MMC 分支里的逻辑就是：在 FAT 分区上找到 `/image.ub` → `fatload … 0x10000000 image.ub` → `bootm`。

### A.3 接线 + 上电

1. **HDMI 线**：板上 **HDMI TX** → 显示器；小屏记得**另接 USB 5V 供电**。
2. **USB UART 线**（可选但强烈建议）：板上 **USB UART** → 电脑，用来收 Linux 日志。
3. **SD 卡**：插进板上 Micro SD / TF 卡槽。
4. **DC5V 电源**：插上，然后打开板上**电源开关**。

### A.4 预期现象

- **HDMI 直接出现游戏主菜单**（同第 3 节「画面验证」的描述）。
- K4~K7 照常可玩（PL 侧逻辑与 `p2d3` 基线**一行未改**）。
- 串口（可选）：用 **115200 / 8N1** 打开 **USB UART** 对应的 COM 口，应打印 Linux 内核启动日志，
  最终进入 shell。

> 串口工具随便挑（MobaXterm / PuTTY / SecureCRT / 串口助手），**115200 8N1、无流控**。
> 设备管理器中它会显示为 **Silicon Labs CP210x** 的 COM 口。

## 方式 B：JTAG 直接下载（保底 · 纯 PL）

> 特点：**不依赖 SD 卡**，只要有电脑和 USB 线就能出画面。**这是比赛保底方案。**

### B.1 接线

1. **HDMI 线**：板上 **HDMI TX** → 显示器。
2. **USB 线**：板上 **USB JTAG**（Micro-USB）→ 电脑 USB 口。
3. **DC5V 电源**：插上，**先别开电源开关**。

### B.2 让电脑认出开发板

1. 打开 **Vivado 2026.1**。
2. 点左侧 Flow Navigator 最下面的 **Open Hardware Manager**（或菜单 Flow → Open Hardware Manager）。
3. 点上方的 **Open target** → **Auto Connect**。
4. **成功标志**：下方 Hardware 窗口里出现 `xc7z020_1`。

连不上 → 看「常见问题一」。

### B.3 下载位流（核心 3 步）

1. 打开开发板**电源开关**（板上电源指示灯亮 = 供电正常）。
2. 在 Hardware 窗口里 **右键** `xc7z020_1` → 选 **Program Device...**。
3. 弹出的窗口里，**Bitstream** 一行点右边的 `...` 按钮，选中：

   ```
   D:\FPGAproject\MizarZ7_GameConsole\bit\top_game_console_p2d3.bit
   ```

4. 点 **Program**。下方绿色进度条走完、Vivado 底部提示 `Program/Verify successful` 即成功（约 5 秒）。

> 补充：`D:\FPGAproject\MizarZ7_PLPS\top_ps.bit` 也可以用同样的方式下载（它的 PL 逻辑与 `p2d3` 相同，
> 游戏画面一样）。区别是它内部还带 Zynq PS 模块，但 JTAG 单独下载**不会**让 PS 起 Linux。
> 想跑 Linux 请用方式 A。

## 第 3 步：验证成功（两种方式共用）

### 3.1 LED 验证（先做这个，确认按键通路）

按住任意一个用户按键，**对应的 LED 会亮**，松开就灭：

| 按键（板上位号） | 对应 LED（板上位号） |
| --- | --- |
| K4 | D6 |
| K5 | D7 |
| K6 | D8 |
| K7 | D9 |

> 手册依据：3.7.5 节（p39）"PL 侧提供了四个用户按键（K4~K7）"；3.7.6 节（p40）"四个用户 LED（D6~D9）"，
> 输出低电平时亮。丝印上是 PL KEY1~4 / PL LED1~4，位号分别是 K4~K7 / D6~D9。
> **K1 是复位键（丝印 RESET），别按错。**

### 3.2 屏幕验证（应该看到游戏主菜单）

- **竖渐变背景**：画面顶部到下方颜色由深蓝逐步过渡到品红，共 10 条色带
- **一圈 2 像素宽的青色边框**，紧贴内侧还有 2 像素深的暗色内衬
- **边框上有一小段亮黄色光带**沿上下边框从右往左扫动（循环）
- **标题 "GAME CONSOLE"**：琥珀色大字（4 倍缩放），带深色投影，颜色缓慢明暗呼吸
- **两个菜单项 "SNAKE" 和 "TETRIS"**（白色大字）
- **选中项**落在一条**亮绿色横条**上（带亮黄描边），文字为黑色

满屏 / 不满屏取决于显示器，**两种都正常**：

- 接 **480×320 的 3.5 寸小屏**（本工程标定用的 LCDWiki MPI3508）：画面**铺满整屏**，且 1:1 点对点，无拉伸损失。
- 接**电脑显示器 / 更大的屏**：画面出现在**左上角一块 480×320 的窗口**里，其余为黑色。

> 原理：本工程输出帧为 **800×525 @ 25.2 MHz（行频 31.5 kHz / 场频 60 Hz）**，其 HS / VS 速率
> 正好等于标准 640×480@60，所以各类显示器都认；有效画面 480×320 位于帧内，带 scaler 的小屏
> 会把它 1:1 映射到原生 480×320 面板。
>
> ⚠️ **不要为此改成"原生 480×320 时序"**：那需要约 12.6 MHz 像素时钟，低于 HDMI/DVI 接收端
> 25 MHz 的硬性下限，显示器会**直接报无信号**（本工程已实测否决该方案）。

### 3.3 操作与按键行为

**按键物理位置**：K4~K7（板上丝印 PL KEY1~4）；**K1 是复位键（丝印 RESET），别按错**。
按键与 LED 对应仍为 K4→D6、K5→D7、K6→D8、K7→D9（按住即亮，用于确认按键通路）。

#### 3.3.1 主菜单

| 按键 | 功能 |
| --- | --- |
| **K4**（短按） | 选中项上移（选 SNAKE） |
| **K7**（短按） | 选中项下移（选 TETRIS） |
| **K5**（短按 / 长按 0.6 秒） | 进入选中的游戏 |

#### 3.3.2 贪吃蛇

场地：28×18 格、每格 16 像素；蛇身鲜绿色，蛇头黄色；食物红色。

| 按键 | 功能 |

| **K4**（短按） | 向左转 |
| **K5**（短按） | 向右转 |
| **K6**（短按） | 向上转 |
| **K7**（短按） | 向下转 |

画面上方显示 `SCORE nn`（吃到一格 +1，上限 99）。

## 常见问题

### 问题一：Vivado 里 Auto Connect 找不到硬件（方式 B 最常见）

**原因**：电脑没装 FPGA 下载线驱动。

**解决**（一次搞定）：

1. **关掉 Vivado**。
2. 用**管理员身份**运行驱动安装程序（右键 → 以管理员身份运行）：

   ```
   D:\Program_Files\AMD\2026.1\data\xicom\cable_drivers\nt64\install_drivers.cmd
   ```

3. 按提示一路确认安装完。
4. **拔掉 USB 线，再插回去**（这步很重要，让驱动重新加载）。
5. 打开 Vivado，重新 Auto Connect。

### 问题二：连接上了，但 Program 报错

- 确认选的 `.bit` 路径正确，文件大小约 **4 MB**（4,045,771 字节）。
- 确认板子已上电、USB 没松动。
- 确认 USB 线插的是 **USB JTAG** 口，不是 **USB UART** 口。

### 问题三：显示器「无信号 / No Signal」

按可能性从高到低排查：

1. **HDMI 线插在 HDMI RX 上了** → 换到 **HDMI TX** 口。
2. 小屏没单独供电 → 给显示器接 **USB 5V 1A**。
3. HDMI 线或显示器口有问题 → 换线 / 换显示器另一个口试。
4. 显示器输入源没切到 HDMI → 用显示器按键手动选 HDMI 输入。
5. 换一台显示器试（有些老显示器对非标准分辨率兼容性差）。

### 问题四：有画面但花屏 / 闪烁 / 颜色错乱

- 确认用的就是本工程给的位流（没自己重新编译过）。
- 换一根质量好一点的 HDMI 线（劣质线是花屏头号原因）。
- 缩短 HDMI 线长度（建议 2 米以内）。

### 问题五：画面偏色（整体发红 / 缺蓝色）

- 换成工程原始 `.bit` 重新 Program 一次；若仍偏色，说明某一路 TMDS 通道硬件接触不良，
  换线或用另一个 HDMI 口交叉验证。

### 问题六：按键没反应，但画面正常

- 先看 LED：按 K4，D6 是否亮？
  - **D6 亮** → 按键通路正常，问题在游戏逻辑（把现象告诉我）。
  - **D6 不亮** → 按键通路问题，检查是否按对了 K4~K7（别按到 K1 复位键 RESET）。

### 问题七：K5 一按就把方块"甩"下去 / 想右移却触发了加速

- K5 是**复用**键：短按（<0.6 秒）＝右移，长按（≥0.6 秒）＝加速下落。
  想右移就**轻点一下立刻松手**；想加速就**一直按住不放**。

### 问题八：每次断电后程序就没了

- **方式 B 正常现象**：位流下载到 FPGA 是**掉电丢失**的，每次上电要重新下载。
- **方式 A 不会**：`BOOT.BIN` 在 SD 卡上，上电自动运行。
- 想**不插 SD 卡也自动运行** → 见「附录 C」。

### 问题九：方式 A 下 HDMI 有画面、但串口没有任何输出

- 检查串口参数：**115200 / 8 / N / 1 / 无流控**。
- 检查插的是 **USB UART** 口（CP2102，设备管理器显示 `Silicon Labs CP210x`），不是 USB JTAG。
- 检查 SD 卡里 `image.ub` / `boot.scr` 是否拷在**根目录**（不是子文件夹里），文件名别改。
- 画面正常但串口无输出，**不影响玩游戏** —— 说明 PL 已被 FSBL 配好，只是 Linux/U-Boot 那一步有问题。

### 问题十：方式 A 下上电后 HDMI 黑屏，且串口也无输出

- 大概率是 **SD 卡没被识别**。依次检查：
  1. SD 卡是否插到位（板上 Micro SD / TF 卡槽）。
  2. SD 卡是否为 **FAT32**、分区表是否 **MBR**、`BOOT.BIN` 是否在**根目录**且文件名全大写。
  3. 换一张卡试（个别卡兼容性差；建议 Class10、≤32 GB）。
  4. J1 是否确实拨到了 **SD 档（两位都 OFF）**。
- 应急：先切到**方式 B（JTAG）**把位流下进去确认板子是好的，再回头查 SD。

## 附录 C：QSPI 固化（进阶 · 可选，当前未验证）

> 标准做法是让程序**开机自动运行**，不必每次插 SD 卡。**当前建议先用方式 A（SD 卡）**，
> 等比赛前再固化。

**板上 Flash 已确认**（手册 3.6.2 节 p20）：型号 **W25Q256FVEI**（Winbond），
容量 **256 Mbit = 32 MB**，3.3V CMOS，**Quad（x4）**，接 PS BANK500 MIO[1-6]。

### C.1 纯 PL 版（只放位流）

在 Vivado Tcl Console 里（先把当前目录切到 `bit`）：

```tcl
cd D:/FPGAproject/MizarZ7_GameConsole/bit
write_cfgmem -force -format mcs -interface SPIx4 -size 32 \
  -loadbit "up 0x0 top_game_console_p2d3.bit" \
  -file top_game_console_p2d3.mcs
```

然后：Hardware Manager 连上 `xc7z020_1` → 右键 `xc7z020_1` → **Add Configuration Memory Device**
→ 搜索 **W25Q256** 选 **W25Q256FVEI** → OK；再右键该 Flash → **Program Configuration Memory Device**
→ Configuration file 选刚生成的 `.mcs` → OK。
**最后把 J1 拨成 QSPI 档（1 = OFF，2 = ON）** 重新上电。

### C.2 PS+PL 版（需放 `BOOT.BIN`）

PS+PL 的 QSPI 启动要求 `BOOT.BIN` **和 rootfs 镜像都在 Flash 内**，需要专用分区布局
（设备树里已定义 `qspi-boot` / `qspi-kernel` / `qspi-bootenv` 三个分区），
不能用 C.1 的纯位流方式。

**状态：尚未制作/验证。** 计划做法是生成 QSPI 专用镜像后再用 Vivado
`Program Configuration Memory Device` 写入（或 Linux 下用 `flashcp`）。
在它完成之前，**请用方式 A 的 SD 卡启动**。
